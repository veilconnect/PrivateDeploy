# 插件：安全模型与风险提示

> English version: [PLUGINS.md](PLUGINS.md)

## 插件是被完全信任的代码

PrivateDeploy 桌面版插件（插件页 → 插件中心或手动添加）是**直接在应用内部
执行、没有任何沙箱隔离**的 JavaScript 程序。插件以与应用本身相同的权限运
行，并拥有应用原生桥接层的全部能力。具体来说，一个已安装并启用的插件可以：

- **读取和修改你的文件** —— 应用进程能访问的任何内容，包括应用保存的配置
  文件、订阅和节点凭据。
- **访问网络** —— 向任意地址发送请求，也就意味着可以向任意地址外传数据。
- **在本机执行命令** —— 通过应用的 exec 桥接启动本地进程。

插件没有能力/权限声明机制：每个插件都隐含拥有上述全部能力。因此应用会在
**添加任何插件之前**（无论来自插件中心还是手动表单）弹出完全信任风险警告，
并要求你显式确认。将来即使引入能力声明机制，未声明能力的插件也必须继续按
完全信任对待并展示完整警告。

**请只安装你信任其作者与来源的插件。**安装插件等同于在你的电脑上运行一个
来历不明的程序，请以同样的谨慎对待。

## 应用提供（以及不提供）的保护

应用在插件**分发环节**有两道轻量防线——注意它们都不限制已批准代码运行后
能做什么：

1. **来源白名单。**远程插件代码只能通过 HTTPS 从白名单主机（GitHub 上的
   官方 GUI-for-Cores 插件中心）获取；重定向逐跳重新校验，开放重定向无法
   把下载引到任意源。
2. **代码哈希固定（首次使用即信任）。**插件代码在首次安装时以 SHA-256 固
   定。之后代码一旦漂移——远程更新或磁盘篡改——插件将拒绝加载/更新，直到
   你显式重新批准变更后的代码。

这两道防线降低的是"收到你没要求的恶意代码"的风险；它们**不会**限制你已批
准的插件：被你批准的恶意插件仍然拥有上文所述的全部能力。

## 实用建议

- 优先使用官方插件中心的插件，安装前用应用内"源码"按钮浏览一下代码。
- 当应用提示"插件代码已变更"时，除非你明白变更原因（例如你已读过更新日志
  的正常升级），否则不要重新批准。
- 不再使用的插件请及时禁用或删除。
- 永远不要安装私下发给你的、或托管在白名单来源之外的插件，哪怕对方声称
  "只需要临时放行一次"。
